# Brief: survey-server

CONTEXT. OnniCode (this repo; read AGENTS.md first) is a local cockpit that runs AI coding-agent tasks, each in its own git worktree. The owner wants a NEW feature, separate from (not replacing) the existing "Automations": a PROJECT GRAPH - the repository represented as nodes and edges (modules, files, symbols, tests, docs, contract schema->route->client->hook chains, git co-change, agent runs touching nodes). It must (a) let users SEE and understand links inside the project visually in the cockpit, and (b) let agents query it (CLI such as onni graph neighbors/impact/path/context, with a token budget) together with the project-context layer. The graph is built and updated BY CODE (deterministic static analysis + git history, incremental by commit/content hash, cached under .ai/onni/, never required, zero-config, local-first, no upload); an LLM-written summary layer is optional, OFF by default, labelled as AI-written. Edges carry provenance (extracted/inferred/declared). It will also be used by the manager-worker system (partition scopes into disjoint regions, predict conflicts, pick tests for verify).

We are in a SURVEY + PLANNING phase: NOTHING is built yet. YOUR JOB IS RESEARCH ONLY. Do not change any file except the single markdown report named in your order. Write the report in Vietnamese prose with English identifiers/paths/URLs. Be precise and verifiable: cite file paths with symbols (grep to confirm; line numbers may be approximate), cite URLs for external facts with the date you fetched them, and mark anything you could not verify as "chua kiem". Never invent. If you lack network access or a tool, say so explicitly in the report and in your final report instead of guessing. Keep the report focused and skimmable (tables where useful), no more than about 600 lines. Commit the report on your branch with a conventional commit like docs(graph): <subject>. When done call onni task report with status, a 5-line summary, and the report path.
