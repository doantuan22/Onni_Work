# Nghiên cứu engine phân tích mã và bản đồ repo cho agent

## Phạm vi và cách kiểm chứng

Đây là khảo sát công cụ hiện có để định hình Project Graph cho OnniCode; không đề xuất thêm dịch vụ hosted hoặc thay thế Automations. Tôi đã mở repo/tài liệu upstream và lấy license, ngôn ngữ chính GitHub, số sao cùng ngày commit mới nhất bằng GitHub REST API. Số sao là snapshot tại ngày truy cập, không phải bằng chứng về khả năng scale. Benchmark do dự án tự công bố được ghi rõ là số liệu upstream, chưa được kiểm thử độc lập.

Danh sách có 22 dự án/công cụ. 17 repo có commit trong sáu tháng trước ngày truy cập. Một số công cụ được brief nêu đích danh nhưng ít cập nhật hoặc đã ngừng hỗ trợ; chúng được giữ lại làm tư liệu so sánh và được đánh dấu, không tính vào nhóm lựa chọn đang hoạt động.

## Tóm tắt

- Không có một engine nào trong khảo sát đồng thời cung cấp AST/type resolution tốt cho TypeScript, đa ngôn ngữ, graph provenance, cập nhật cục bộ, UI nhúng, API/CLI ổn định và gọn đủ để OnniCode dùng trực tiếp.
- MVP TypeScript nên tự tạo graph từ TypeScript Compiler API (qua lớp adapter theo phiên bản); dùng ts-morph để giảm công sức thao tác AST. Giữ tree-sitter làm parser fallback về sau, không coi cú pháp parse được là bằng chứng cho call/reference edge.
- SCIP là định dạng trao đổi navigation hữu ích; scip-typescript cung cấp edge symbol có resolution, nhưng là indexer batch có memory trade-off và hiện yêu cầu Node 22/24. Nó không khớp ngay với nền Node 20+ của OnniCode.
- Aider chứng minh cách xếp hạng context theo token hữu ích cho agent. Repomix chứng minh cách giao cả repo dưới dạng gói, nhưng cả hai không phải graph có thể query theo impact/path.
- code-graph-rag và CodeGraphContext là ví dụ gần nhất với graph local, CLI/MCP và sync tăng dần. Chúng cũng cho thấy chi phí quản lý graph schema, runtime, backend, dependency closure và an toàn khi chạy MCP.
- Git co-change hữu ích như một loại edge riêng có trọng số và khoảng thời gian. Nó là tín hiệu lịch sử, không phải quan hệ phụ thuộc tĩnh; git-of-theseus đo tuổi thọ dòng mã, không tính co-change.

## Khuyến nghị engine strategy

### 1. MVP TypeScript-first, rồi mở rộng đa ngôn ngữ

Dùng TypeScript Program/TypeChecker làm nguồn có độ tin cậy cao cho file, package, symbol, import, type/reference và call edges. Đọc workspace/tsconfig để phản ánh paths, project references và package boundaries. ts-morph chỉ nên được chọn nếu nó làm code traversal dễ hơn mà không cản version upgrade.

Tạo GraphExtractor seam độc lập với storage và HTTP. Thêm tree-sitter làm structural fallback cho ngôn ngữ chưa có semantic adapter; gắn rõ mức chắc chắn của fallback. SCIP có thể là importer tùy chọn cho repos lớn/cross-language; scip-typescript chưa phù hợp default vì yêu cầu Node 22/24. Kiểm tra tương thích TypeScript 7.1 trước khi chốt TypeScript API.

### 2. Incremental update

- Cache dưới .ai/onni/ như artifact có thể xóa và dựng lại; record content hash, parser/indexer version, config/tsconfig hash, branch/head commit và graph schema version. Không dùng mtime đơn lẻ để xác định nội dung.
- Khi file đổi, thay nodes/edges phát sinh từ file trong một transaction. Re-resolve inbound import/call candidates bị ảnh hưởng; không chỉ cập nhật outgoing edges. File rename/delete phải xóa cạnh cũ rõ ràng.
- Theo dõi git log riêng; thêm commit co-change edges theo batch đến lastIndexedCommit. Không buộc mỗi file save quét lịch sử Git đầy đủ.
- Dùng incomplete-index marker và chỉ công bố snapshot sau khi batch thành công. Lỗi parser hoặc bị dừng thì phục hồi bằng retry/full rescan; không phục vụ graph nửa ghi.
- Có full rebuild path luôn hoạt động. Cache mất, schema đổi, branch khác hoặc config resolution đổi thì dựng lại an toàn.
- File watcher là tối ưu; mở cockpit/agent CLI cũng phải so hash để catch missed events.

### 3. Edge provenance

Tách kind khỏi source:

- extracted: parser/compiler xác nhận được, ví dụ imports, calls, defines, implements.
- declared: lấy từ package/workspace config, test naming/config, route schema hoặc annotation.
- inferred: heuristic như basename match, likely test coverage hoặc git co-change.

Mỗi edge lưu extractor, extractorVersion, sourcePath + range/line nếu có, observedAt hoặc commit SHA, confidence/reason cho inference. Không trộn heuristic với edge đã resolve; UI và agent filter được theo độ tin cậy. Dynamic import chưa giải được phải là unresolved candidate, không bịa target.

### 4. Agent query trong token budget

Expose read-only CLI như onni graph neighbors, impact, path, context cùng API schema có giới hạn depth, limit, maxTokens và filter edgeKind/provenance. Trả path ngắn, symbol signature, location, confidence và lý do chọn node; CLI nên xuất JSON ổn định cho workflow và dạng text cho prompt.

Dùng hai lớp: graph query trả lời câu hỏi chính xác (ai gọi, tests nào bị ảnh hưởng, đường đi giữa route và hook); ranked repo map theo kiểu Aider đưa thêm vài symbol liên quan để agent có ngữ cảnh. Tính token từ serializer thực tế, dành budget cho nội dung khác trong prompt, và dừng cứng ở cap. Đừng dựa vào PageRank/map để thay câu trả lời có đường dẫn chứng minh.

### 5. Tương thích OnniCode

Onni đã có CLI trong packages/work/src/index.ts (runCommand()), local repo state trong .ai/onni/ (packages/work/src/data-gitignore.ts, ensureDataGitignore()), home state qua packages/work/src/paths.ts (onniHomeDir()), và typed HTTP contract trong packages/contract/src/repo.ts (repoTreeSchema, repoFileQuerySchema). Gắn API mới vào contract + route family và @onni/api-client; không tự thêm loose Hono route. Cockpit dùng một WS bus tại /api/v1/ws (packages/work/src/server/ws.ts, packages/web/src/api/ws.ts); graph status/change nên là topic demand-driven thay vì polling. Khi ghi config, dùng mergeWriteWorkspaceConfig() theo quy tắc repo. [AGENTS.md](../../../AGENTS.md).

Graph builder, storage, CLI query và UI visualization nên là các consumer cùng một graph schema versioned. UI nên render neighborhood/impact theo cụm có giới hạn, hiển thị loại edge/provenance và mở source file tại location. Chỉ index trong repository local; graph cache là optional, không điều kiện để cockpit boot. LLM summary để tắt mặc định và lưu riêng như nội dung được tạo bởi AI.

## Cạm bẫy cần tránh

- **False edges:** tên trùng, barrel exports, overloads, generated declaration files và AST pattern có thể gắn nhầm symbol. Giữ unresolved/ambiguous thay vì tạo cạnh chắc chắn giả.
- **Dynamic imports/reflection:** require(variable), dynamic import(), plugin registries và runtime reflection không luôn giải được tĩnh. Lưu specifier/candidate + lý do không resolve; nếu có runtime trace thì ghi nguồn khác.
- **Monorepo/workspace:** tsconfig references, package.json exports/imports, pnpm symlink, Yarn PnP, project root lồng nhau và package aliases làm resolver phải hiểu workspace. Định danh node cần gồm repo + package + path, không chỉ basename.
- **Tests:** test discovery không chỉ *.test.ts; framework config, generated tests, fixtures và colocated tests cần edge provenance riêng.
- **Generated/vendor code:** áp dụng .gitignore, config generator và exclude defaults; tránh bơm bundle/minified/vendor vào graph. Giữ trạng thái generated/ignored khi có rule khai báo.
- **Repo lớn:** parser memory, đồ thị triệu cạnh, fanout hub và rendering tất cả nodes làm UI/agent vô dụng. Query bounded, paginate, group packages, cache từng file, giữ DB query có index và benchmark trên repo thật.
- **Windows paths:** normalize separator, drive letter, UNC, case-insensitive lookup, junction/symlink và Git worktree path; không dùng path display làm global node ID. Kiểm tra file watcher khi editor rename bằng atomic-save.
- **Missed events:** watcher có thể bị tắt, process crash hoặc event coalesce; cần content-hash reconciliation và full rebuild.
- **License/runtime:** parser grammar/license khác engine license; GPL tool cần review trước embedding. Kiểm tra minimum Node/Python/JDK và native wheel cho Windows, không assume package JS/Rust tự tương thích.
- **Git coupling:** commit lớn/refactor/formatting tạo co-change noise. Loại commit máy móc khi có thể; edge cần count, time window, confidence và commit provenance, không được hiển thị như import/call.
- **Graph safety:** local MCP/CLI cần read-only mặc định, cap cho path/depth/nodes/bytes, không nhận Cypher tự do từ agent và không trả code snippet quá token budget.
